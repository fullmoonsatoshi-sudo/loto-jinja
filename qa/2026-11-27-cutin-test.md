# QA報告：神託のご祈祷カットイン／キャリーオーバー書き足し（2026-11-27）

担当：QA（テスター）　対象：`main` d472657 ＋ 作業ツリー（未コミットの app.js 2行・oharai 画像8枚）
環境：Chrome（Playwright・375×812・Asia/Tokyo・Service Worker 無効）、http://localhost:8766/index.html、Node v22
スクリーンショット：`/home/claude/qa-shots/`

## 結論

**このままでは公開不可（いいえ）。**
手元の画面ではカットインは仕様どおり動いた（4キャラとも oharai1/oharai2 が交互に出て、約2.6秒で白く光って消え、結果までスクロールする）。
ただし **oharai の絵8枚と、絵を先に読み込む app.js の変更がコミットされていない**。公開（GitHub Actions が `src` をそのまま Pages に上げる）はコミットされた内容から作られるので、このまま出すと本番では全キャラが「お祈りの絵を揺らす」代わりの動きになり、仕様1・2を満たさない。
コミットすれば公開できる水準。そのほかの問題は中・低で、公開を止めるほどではない（中の2件は次の修正で直すのがよい）。

自動テスト `node tools/test.mjs`：**46件すべて合格**（ただし set-carryover.mjs のテストは無い）。
本物の `src/data` は変更なし（`git status --short src/data` は空）。

## 見つけた問題（重要度の高い順）

### 【高】1. oharai の絵8枚と app.js の先読みがコミットされていない
- 再現手順：`git -C /home/claude/loto-jinja status --short`
- 期待：カットインに要るファイルがすべてコミットされている
- 実際：`?? src/assets/characters/*/oharai1.png・oharai2.png`（8枚とも未追跡）、` M src/app.js`（先読みの2行）。`git ls-files` で oharai は0件。`.github/workflows/deploy.yml` は checkout した `src` を上げるので、本番には絵が無い。route で oharai を404にしたときと同じく、本番では全キャラが代わりの「お祈り」の絵になる（スクショ `404-miko-0.8s.png`）。
- 対応：8枚と app.js をコミットしてから公開する。

### 【中】2. 「神託をいただく」をダブルタップ（連打）すると、カットインがすぐ消える
- 再現手順：神託画面で「神託をいただく」をダブルクリック、または約250ms以内に2回タップ
- 期待：カットインが約2.6秒出る（タップでとばすのは、カットインが出たあとにわざと押したとき）
- 実際：1回目でカットインが出て、2回目のタップがその上に当たって「とばす」扱いになる。カットインは約0.3〜0.6秒で消える（ダブルクリック0.56秒・250ms間隔2タップ0.67秒・3連打0.44秒）。ボタンを2回押しがちな人には目玉の演出がほぼ見えない。結果は正しく出る（壊れはしない）。
- 案：出てから0.3〜0.5秒ほどはタップでとばさない、など。

### 【中】3. 動きを減らす設定（reduced-motion）でも、2枚の絵が高速で入れ替わる
- 再現手順：`reduced_motion='reduce'` で「神託をいただく」
- 期待：短く「静かに」出る
- 実際：短くはなる（約0.7秒で消える）。帯・文字は止まり、揺れ・きらめきも止まる。しかし 170ms ごとの oharai1/oharai2 の切り替えは止まらず、0.7秒の間に3回入れ替わる（`setInterval` が reduce を見ていない）。動きを減らしたい人に、パラパラ動く絵を見せることになる。
- 案：reduce のときは切り替えをせず1枚（oharai1 か pray）だけ出す。

### 【中】4. set-carryover.mjs：CSVに「キャリーオーバー」行が無いと、記録済みの額を null で上書きしてから落ちる
- 再現手順（/tmp のコピーで実施）：公式CSV A1022157.CSV から「キャリーオーバー」の行を消したファイルで `node tools/set-carryover.mjs loto6 <そのファイル>`
- 期待：書かずにエラー終了（記録済みの 233,461,295円 はそのまま）
- 実際：本数字などが一致するので先へ進み、`carryover: null` を書き込み（記録済みの額が消える）、そのあと `off.carryover.toLocaleString` で TypeError、終了コード1。ホームのキャリーオーバー表示が消える。公式CSVが途中までしか取れなかったときなどに起こりうる。
- 案：`off.carryover` が数値でなければ書かずに終了する。

### 【低】5. カットイン中もキーボードで後ろの操作ができ、Escape ではとばせない
- 再現手順：Enter で「神託をいただく」→ Tab で後ろのボタンへ移動して Enter
- 実際：カットインの後ろのくじの種類（ロト7）・タブ・設定が操作できる。くじを切り替えた場合は「くじの種類を切り替えたので、神託は取り消しました」と出て結果は混ざらない（対策は効いている）。タブを切り替えても結果は保たれ、神託に戻ると出ている。設定はカットインの上に開く。Escape ではとばせない。開始後フォーカスは body に落ちる。
- 案：カットイン中は後ろを `inert` にする、Escape でとばす、フォーカスをカットインに移す。

### 【低】6. あたる（kannushi）の oharai1.png に白っぽい四角いもやがある
- 大幣のまわりに半透明の四角（画素の約14%が半透明。ほかの絵は1〜4%）。朱の帯の上で四角が少し見える（`kannushi-zoom.png`）。
- 案：背景を抜き直す。

### 【低】7. 振る絵もお祈りの絵も読めないと、こわれた画像の枠が揺れる
- 再現：`**/miko/*.png` をすべて404 → カットインの真ん中にこわれた画像の枠が出て揺れる（`404all-miko-0.8s.png`）。オフラインで初めて神託を開いた場合など（sw.js の SHELL にキャラ画像は入っていない）。めったに起きない。

### 【低】8. 横向き（812×375）ではキャラが画面からはみ出す
- 絵の箱が `min(84vw, 420px)` の正方形で、高さ375に入らない。頭と足が切れ、名前とひとことが体に重なる（`landscape-812x375.png`）。縦向き375×812では問題なし。

### 【低】9. set-carryover.mjs：くじの種類を間違えると、終了コード1とスタックトレースで落ちる
- `loto7` にロト6のCSV、`loto6` にロト7のCSVを渡すと、parseCsv が例外を出して終了コード1（データは書かない）。CSVが壊れている・ファイルが無いときも同じ。決めてある終了コード（2/3/4）以外なので、定期タスク側は「1＝読めないCSV」として扱う必要がある。set-carryover.mjs の自動テストも無い。

### 参考（問題ではない）
- カットイン中にブラウザの「戻る」を押すとアプリから出る（前のページへ戻る）。アプリはもともと履歴を使っていないので、今回の変更で変わったことではない。「進む」で戻ると、カットインは無く普通に開く。
