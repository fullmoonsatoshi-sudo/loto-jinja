# 仕様書：当たれ！ロト神社（loto-app）

- 作成日：2026-11-26
- 作成者：engineer
- 元にした企画書：`docs/proposal.md`
- 元にしたキャラ設定：`docs/characters.md`

## 1. 技術構成
- 種類：ブラウザで動く Web アプリ（PWA）。後で Android アプリに包んで（TWA）Google Play に出す
- 言語：HTML + CSS + JavaScript（ライブラリなし。ビルド不要）
- データ：`src/data/loto6.json`、`src/data/loto7.json`（全回の当せん番号・口数・当せん金額）、`src/data/miniloto.json`・`bingo5.json`・`numbers3.json`・`numbers4.json`（全回の当せん番号。当せん金は分かる回だけ）
- 利用者のデータ（マイ番号、設定）：端末のブラウザ内（localStorage）だけに保存。サーバーには送らない
- オフライン：Service Worker。すべて「通信を優先、つながらないときだけ保存分」を使う（修正版や新しい結果が必ず届くように）

## 2. データ
- 取り込み元：みずほ銀行の公式当せん番号。初回分は公開されている全回データ（GitHub: jjayck/lotoanaba-data）を取り込み、公式ページと9回分を照合して一致を確認済み（第45・115・130・154・157・161・201・261・333回）
- 自動更新：`tools/update-data.mjs` がまず公式の回別 CSV（ロト6：`A102<回>.CSV`、ロト7：`A103<回>.CSV`）を試す。公式はクラウド（GitHub Actions）からのアクセスを403で拒否するため（2026-11-26 本番で確認）、そのときは予備の公開データ（jjayck/lotoanaba-data、`tools/mirror.mjs`）から取り込む。予備データは、取り込み済みの直近20回と完全一致し、meta.json の SHA-256 と一致したときだけ使う。予備経由の回にはキャリーオーバーが無いため、抽せんの翌朝（火・金・土 7:40）に Claude の定期タスクが公式CSVを読み、`tools/set-carryover.mjs` で書き足す（公式CSVと取り込み済みの本数字・ボーナス・口数・金額が完全一致したときだけ）。`.github/workflows/deploy.yml` で抽せん日の夜（月・木・金 19:00〜23:30 に30分おき＋翌朝7時）に自動実行
- 形式：`{ n: 回, date: "YYYY-MM-DD", main: [本数字], bonus: [ボーナス数字], winners: [等級ごとの口数], prizes: [等級ごとの当せん金額] }`
- キャリーオーバー：公式CSVの「キャリーオーバー」行から取り込む（`carryover`）。第2157回（ロト6）・第704回（ロト7）以降は値あり。それより前の回は取り込み元に無いため表示しない（ホームは常に最新回なので必ず表示される）
- 公式CSVの形式（実物は `tools/fixtures/`）：Shift_JIS、日付は和暦（令和）、等級は全角（１等）。読み取りは `tools/csv.mjs`

## 3. 機能ごとの仕様

### 機能1：当選番号速報＆過去結果（ホーム・結果一覧）
- ロト6／ロト7 を上部で切り替え
- 最新回：回・日付・本数字・ボーナス数字・等級ごとの口数と金額
- 次回抽せんまでのカウントダウン（ロト6：月・木 18:45、ロト7：金 18:45、日本時間）
- 抽せん時刻を過ぎてもデータが未反映のときは「結果の取り込み待ち」と表示
- 結果一覧：新しい順に50回ずつ表示、回番号で検索

### 機能2：マイ番号の自動当選チェック
- 数字パッドで本数字を選んで登録（ロト6は6個、ロト7は7個、1〜43／1〜37、重複不可）
- 対象の回（既定は次回）を指定
- 登録済みの番号を、その回の結果と照合して等級を表示
  - ロト6：1等=6個一致／2等=5個＋ボーナス／3等=5個／4等=4個／5等=3個
  - ロト7：1等=7個／2等=6個＋ボーナス（2個のうちどちらか）／3等=6個／4等=5個／5等=4個／6等=3個＋ボーナス1個以上
- 当たりがあればキャラが大喜び、全部はずれならしょんぼり
- 削除は確認してから

### 機能3：神託（番号予想）＋傾向分析
- 「神託をいただく」を押すと、キャラが画面いっぱいに割り込むカットイン（約2.6秒・タップでとばせる）。持ち物を左右に振る2枚の絵（oharai1/oharai2）を交互に出してご祈祷の様子を見せ、その後に結果を出す。絵が無いキャラはお祈りの絵を揺らして代わりにする
- 流派：よく出る派（直近100回の出現回数で重み付け）／ご無沙汰派（出ていない回数で重み付け）／バランス派（奇数の数と合計値を過去の多い範囲にそろえる）／運気派（今日の日付と誕生日から決まる。同じ日は同じ番号）
- 口数：1〜5口
- 各口に「人とかぶりにくさ指数」（0〜100）と理由を表示
- 傾向：数字ごとの出現回数グラフ（直近100回／全回）、よく出る数字・ご無沙汰の数字の上位5つ
- 「お楽しみ機能で、当せん確率は変わりません」を常に表示

### 人とかぶりにくさ指数（独自）
- 100点から、人が選びがちな形ほど減点する
  - 誕生日の範囲（1〜31）に偏る／連番／等間隔の並び／同じ十の位に集中／5や7の倍数ばかり／下一桁がそろう／前回の当せん番号をなぞる
- 80点以上「かぶりにくい」、50〜79点「ふつう」、49点以下「かぶりやすい」

### キャラクター
- かなえ（基本）／あたる／こん／ふく を設定で切り替え
- 表情：通常（ホーム）、お祈り（神託中）、大喜び（当たり）、しょんぼり（はずれ）
- 画像が無い表情は通常の画像で代用

### 初回起動
- 「18歳以上向け」「予想はお楽しみ」に同意してから使う

## 6. 追加：ミニロト・ビンゴ5・ナンバーズ3・ナンバーズ4（2026-11-27）

### 6-1. くじのルール（公式どおり。計算は `src/lotto.js`）
| くじ | 数字 | 抽せん | 等級・当せんの種類 |
|---|---|---|---|
| ミニロト | 1〜31から5個（ボーナス1個） | 毎週火曜 18:45 | 1等=5個／2等=4個＋ボーナス／3等=4個／4等=3個 |
| ビンゴ5 | 3×3の盤面（中央FREE）の8マスから1つずつ。マスkは (5k-4)〜5k | 毎週水曜 18:45 | そろったライン数（横3・縦3・斜め2、FREEは常にそろい扱い）：8本=1等／6本=2等／5本=3等／4本=4等／3本=5等／2本=6等／1本=7等（7本はありえない） |
| ナンバーズ3／4 | 0〜9を3桁／4桁（重複・先頭0あり） | 月〜金 18:45（3と4は同じ回） | ストレート／ボックス／セット（ストレート）／セット（ボックス）／ミニ（3のみ・下2桁） |
- 年末年始（12/31〜1/3）は抽せんなし（`nextDraw`。2015年以降の実データで、次回の日付と回の予測がすべて一致することをテストで確認）
- マスの並び：上段(1,2,3)・中段(4,FREE,5)・下段(6,7,8)
- ナンバーズの申込：全部同じ数字（ゾロ目）はボックス・セット不可。ボックスは並びまで一致してもボックスの当せん。セットは並びまで一致なら「セット（ストレート）」、順不同のみなら「セット（ボックス）」
- キャリーオーバーはロト6・ロト7だけ

### 6-2. データ
- 形式：`{ kind, source, updated, draws:[古い順] }`。1回分は `{ n, date, main }`（ミニロトは `bonus` も）。ビンゴ5の `main` はマス順の8個、ナンバーズの `main` は各桁の数字（例 `[0,6,1]`）
- 当せん金：分かる回だけ `winners`（口数）・`prizes`（1口の金額）。ミニロト・ビンゴ5は等級順の配列、ナンバーズは `{ straight, box, setStraight, setBox, mini }`（4は mini なし）。該当なしは 0。分からない回は項目ごと省き、画面では「当せん金は公式発表でご確認ください」
- 出典：公開データ lotto-data-hub（GitHub: tk030-lotto/lotto-data-hub、MITライセンス。元データは loto-life.net。ライセンス文は `src/data/LICENSE-lotto-data-hub.txt`）を元に取り込み。公式（みずほ銀行）との照合は、初回に CEO が直近20回ずつ行い一致を確認しただけで、それ以降の回は公開データの検査（下記）を通ったものをそのまま取り込む。画面・データの `source` には「正式な結果は公式発表でご確認ください」と書く
- 初回分：全回を `tools/init-hub-data.mjs` で取り込み。直近20回の当せん金は公式の値（`tools/fixtures/official/*-recent.txt`）を入れた
- 大きさ（2026-11-27 時点、カッコ内は gzip）：ミニロト 94KB（18KB）、ビンゴ5 32KB（7KB）、ナンバーズ3 330KB（54KB）、ナンバーズ4 344KB（60KB）。アプリは最初に「選んでいるくじ」のデータだけを読み込み、ほかは切り替えたときに読み込む（設定画面を開いたときは取り込み済みの回を出すため全部読む）
- オフライン：Service Worker が最初に保存するデータはロト6・ロト7だけ（従来どおり）。新しい4種類のデータは、そのくじを一度開いたときに保存され、それ以降はオフラインでも見られる
- 自動追記：`tools/update-data.mjs hub`（`tools/hub.mjs`）。公開データ（`https://tk030-lotto.github.io/lotto-data-hub/data/<種類>.json`）から新しい回を追記する。取り込む前に「手元の直近20回と回・日付・数字が完全一致」「回が連続」「日付が増える」「数字が範囲内（ロトは重複なし・ビンゴ5はマスの範囲・ナンバーズは0〜9）」「追記する回が、そのくじの抽せん日（曜日・年末年始の休み。`nextDraw` の予測）どおりの日付で、抽せん時刻を過ぎている」を確かめ、どれか違えば何も取り込まずに失敗。一度に追記するのは最大50回（残りは次の実行で）
- 実行時刻：公開データの更新は日本時間0時〜8時ごろとばらつくため、`.github/workflows/deploy.yml` で月〜金の抽せんの翌朝 6:00〜10:00（日本時間、1時間おき）に実行。画面の案内は「翌朝〜午前中に反映」
- 失敗の扱い：ロト6・ロト7の取り込み（`update-data.mjs loto`）とは別の手順。新しい4種類の取り込みに失敗したとき、または取り込んだあとのテスト（`tools/test.mjs`）が通らないとき（このときは新しい4種類の取り込みを取り消す）も、ロト6・ロト7の保存と公開は続ける。失敗は、公開のあとの `hub-failed` ジョブが失敗になることで分かる（スクリプト単体の終了コードは 3）
- テスト：当せん金のテストは公式の値を入れた回（fixtures の直近20回）で行い、「最新回」は使わない。さらに「4種類すべてに当せん金なしの新しい回を3回ずつ追記した状態でも全テストが通る」ことを、データのコピーで毎回確かめる
- 当せん金の書き足し：`node tools/set-official.mjs <loto6|loto7|miniloto|bingo5|numbers> <公式CSV>`。公式CSVの回・日付・数字（ロトはボーナスも）が手元と完全に一致したときだけ `winners`・`prizes`（ロト6・7はキャリーオーバーも）を書き足す。記録済みの値と食い違えば上書きしない。ナンバーズは1ファイルで3と4の両方に書く（両方そろって一致したときだけ）。終了コードは `set-carryover.mjs` と同じ（0=書いた／記録済み、2=使い方、3=未取り込みの回、4=不一致など、5=CSVが読めない）。公式はクラウドからのアクセスを拒否するので、Claude の定期タスクなどが公式CSVを読んで渡す想定
- 公式CSVの形（実物は `tools/fixtures/official/`、Shift_JIS・CRLF）：ミニロトはロトと同じ形（キャリーオーバー行なし）、ビンゴ5は「ビンゴ５抽せん数字,03,09,…」と１等〜７等、ナンバーズは「ナンバーズ３抽せん数字,412」の後にストレート〜ミニ、続いて「ナンバーズ４抽せん数字」。読み取りは `tools/csv.mjs`（`parseCsv('miniloto')`・`parseBingo5Csv`・`parseNumbersCsv`）。URL は `officialCsvUrl`

### 6-3. 画面
- くじの切り替え：6種類（ロト6・ロト7・ミニロト・ビンゴ5・ナンバーズ3・ナンバーズ4）。幅640px未満は3つずつ2段、それ以上は1段。最後に選んだくじを `lotojinja.game` に保存（6種類のどれかでなければロト6）
- ホーム：最新の当せん番号（ビンゴ5は3×3の盤面、ナンバーズは桁ごとの数字で先頭0も表示）、等級／当せんの種類ごとの口数と金額、次の抽せんまでのカウントダウン。新しい4種類はカウントダウンに「結果は抽せんの翌朝〜午前中に反映されます」。抽せん後で1回分の取り込み待ちのときは、ふつうのお知らせとして「翌朝〜午前中に反映」を案内（2回分以上たまったときは、ロト6・7と同じ強いお知らせ）
- 登録したあと、「対象の回」は次回に戻す
- キャラの「高額の当せん」：1口の当せん金が分かれば10万円以上。分からないときは、ロト6・7は3等まで、ミニロト・ビンゴ5は2等まで、ナンバーズ4はストレートとセット（ストレート）、ナンバーズ3はストレート
- 神託の各口：右上に「かぶりにくい／ふつう／かぶりやすい」、メーターの下に「かぶりにくさ ○点（100点満点）」と理由（360px幅でも1行に収まるように）
- タップ領域：数字パッドは360px幅でも横の間隔を4pxにして1つ44px以上。プライバシーポリシーのリンクも高さ44px
- マイ番号：ミニロトはロトと同じ数字パッド。ビンゴ5は盤面のマスを押してから、そのマスの5つの数字から1つ（選ぶと次の空きマスへ）。ナンバーズは桁を押して0〜9を入れ（入れると次の桁へ）、申込タイプ（ストレート・ボックス・セット・ミニ〔3のみ〕）を選ぶ。ゾロ目ではボックス・セットを押せず、登録もできない。保存は `{ id, game, nums, draw, created }`（ナンバーズは `type` も）。ロト6・7の保存形は変えていない
- 当せんチェック：ビンゴ5は一致したマスを朱で塗り、そろったラインのマスを金の枠で囲み、「そろったライン N本：横・上段…」を出す。ナンバーズは「ボックス当せん！ 14,100円」のようにタイプごとの結果と金額
- 神託：4流派は同じ。ミニロトはロトと同じ。ビンゴ5はマスごとの出現回数／出ていない回数で重み付けして各マスから1つ。ナンバーズは桁ごとの出現傾向（よく出る派・ご無沙汰派）、各桁の合計と奇数の桁の数（バランス派）、運気派（日付と誕生日の種）。ナンバーズは「申込タイプの例」（ゾロ目はストレート、それ以外はセット）を添え、「申込タイプは当たりやすさではなく、当たり方と当せん金の違い」と書く
- 出現の傾向：ミニロトはロトと同じ。ビンゴ5は40個の出現回数（マスごとに色分け）と、マスごとの「よく出る／ご無沙汰」の表。ナンバーズは桁ごとの0〜9の出現回数
- かぶりにくさ指数（100点から減点、当せん確率は変わらない旨の注意書きは同じ）
  - ミニロト：ロトと同じ考え方。ただし全部が1〜31なので、誕生日の代わりに「誕生月の範囲（1〜12）」に偏るかを見る。同じ十の位は4個以上で減点
  - ナンバーズ：ゾロ目（-60）、123/1234のような順番の並び（-55）、同じ数字が3個（-25）・2組（-15）・2個（-5）、となり合う数字（1か所 -8）、左右対称・1212のようなくり返し（-10）、MMDD として正しい月日（ナンバーズ4、-20）、前回と同じ（-30）・前回の並べかえ（-10）
  - ビンゴ5：各マスの一番小さい／大きい数字が5マス以上（-30、8マス全部は -50）、同じ位置の数字が6マス以上（-20）、端の数字ばかり（-15）、前回と同じマスが3つ以上（1つにつき -8、全部同じは -60）
- 設定の「このアプリについて」：ミニロト・ビンゴ5・ナンバーズは「公開データ lotto-data-hub（MITライセンス）を元に取り込み。正式な結果は公式発表でご確認ください」と書き、6種類の取り込み済みの回を表示
- 通信先は今までどおり同じ配信元だけ（データは配信元の `data/` から読む。アプリから外部サイトへは通信しない）
